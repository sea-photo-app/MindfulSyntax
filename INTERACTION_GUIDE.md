# Interaction Guide: японский сад + инженерная точность Apple

> Этот документ объединяет `SKILL.md` (Apple Design: fluid interfaces, springs,
> direct manipulation, materials, typography, reduced motion) с дизайн-идеей
> «Сада кода». Берём **инженерную точность взаимодействия**, но **не переносим
> визуальный стиль Apple**.
>
> Главная формула: **тихий японский сад с отзывчивостью, достойной Apple**.
> Не наоборот.

---

## 0. Что берём и что не берём

### Берём

- Мгновенный отклик на нажатие.
- Прямое манипулирование 1:1: drag-and-drop, ползунки, карта, шторка.
- Прерываемые анимации: пользователь может перехватить движение.
- Пружины с внятными параметрами вместо случайных `cubic-bezier`.
- Передачу скорости и проекцию инерции там, где есть жест.
- Пространственную согласованность: откуда пришло — туда и ушло.
- Резиновые границы вместо жёсткого стопа.
- Мягкие материалы и глубину — **дозированно**.
- Типографику, зависящую от размера: tracking и leading.
- Мультимодальную обратную связь: движение + звук в одном кадре.
- `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-contrast`.
- Восемь принципов как линзу для ревью: purpose, agency, responsibility,
  familiarity, flexibility, simplicity, craft, delight.

### Не берём

- Копирование iOS/macOS: белые панели, SF-контролы, синий акцент, стекло везде.
- Пружины и bounce на каждом элементе. Сад — не спорткар.
- Полноэкранные slide-переходы и агрессивный parallax.
- «Delight = конфетти». Единственное исключение — финальный челлендж.
- Прозрачные карточки поверх 3D и текста: читаемость важнее эффекта.
- Haptic-зависимость: в вебе это ненадёжно; звук опционален.
- Замену нашей типографики на «как у Apple». Serif-заголовки и ханко остаются.
- Модальные подтверждения на каждый шаг.
- Ощущение «продукт Apple», а не «место, где спокойно думается».

## 1. Отклик: нажатие должно чувствоваться сразу

- Визуальный отклик — на `pointerdown`, не на `click`.
- Кнопка: `transform: scale(0.97)` за 100ms `ease-out`; возврат — мягкий.
- Не блокировать ввод во время загрузки Python: показывать статус, но оставлять
  редактор и навигацию доступными.
- Не ставить искусственные задержки «для красоты».
- Микрокопия меняется сразу: «Проверяю…», «Загружаю Python…», «Готово».
- Для Pyodide: честный статус, скелетон/прогресс, но без блокирующего оверлея.

```css
.btn:active { transform: scale(0.97); transition: transform 100ms ease-out; }
```

## 2. Прямое манипулирование

Где пользователь что-то тянет, элемент должен быть приклеен к пальцу.

### «Собери код»

- Переписать drag-and-drop на **Pointer Events** + `setPointerCapture`.
- Учитывать `grabOffset`, а не прыгать в центр.
- Порог 10px, прежде чем считать это drag.
- Клик остаётся доступной альтернативой.
- После отпускания — spring-снап в слот или возврат; скорость можно передать.

### Карта сада

- На мобильном — pan по горизонтали; 1:1 с пальцем.
- Мягкие границы (rubber-band), не жёсткий стоп.
- Инерция после отпускания, но **без** головокружительного скролла.
- Колесо/трекпад на desktop — плавный горизонтальный скролл; не перехватывать
  вертикальный скролл страницы.

### Шторка шпаргалки

- Выезжает справа и уходит вправо.
- На мобильном можно тянуть за край; drag-to-dismiss с порогом и velocity.
- Не блокировать анимацию: если пользователь снова открывает — продолжить
  с текущего положения, а не с нуля.

### Ползунок ёлочки

- 1:1, значение обновляется непрерывно, вывод перерисовывается в том же кадре.
- Никаких «анимация только после отпускания».

### Песочница

- Редактор не должен «прыгать» при наборе.
- Горизонтальный скролл кода — 1:1 с трекпадом/пальцем.
- Кнопка запуска — press-отклик, затем блокировка только на время выполнения.

## 3. Пружины

Внешние библиотеки не подключаем. Нужен маленький локальный spring-helper
(~60–80 строк) или CSS-переходы там, где жест не нужен.

### Значения

| Взаимодействие | Damping | Response |
|---|---:|---:|
| Обычное появление/перемещение | 1.0 | 0.35–0.4 |
| Hover, press, reveal | 1.0 | 0.2–0.3 |
| Шторка / drawer | 0.9 | 0.32 |
| Жест с инерцией (flick) | 0.8 | 0.3–0.4 |
| Финальная награда | 0.75–0.8 | 0.4 |

- По умолчанию **damping 1.0** — без overshoot. Сад не пружинит.
- Bounce только после жеста с momentum: закрытие шторки, бросок карточки,
  финальные лепестки.
- Не использовать фиксированную «duration» для gesture-driven анимаций.
- Анимация начинается от **текущего on-screen значения**, а не от целевого.
- 2D-движение раскладывать на независимые X/Y пружины, если есть разные скорости.
- При прерывании сохранять velocity; не делать «кирпичную стену».

### Где не нужны пружины

- Появление секций при скролле: opacity + translateY, 0.6–0.7s.
- Смена темы: cross-fade, без упругого масштаба.
- Hover карточек: 2–3px, 0.2–0.25s.
- Текст, таблицы, формы: обычные CSS transitions.

---

## 4. Прерываемость

- Не блокировать ввод на время анимации шторки, меню, карты, drag.
- Новая анимация начинается из текущего значения.
- Закрывающуюся шторку можно снова потянуть — она должна следовать пальцу.
- Меню и drawer не должны «доигрывать» закрытие, если пользователь передумал.
- Для модальных сценариев (drawer) допустим scrim, но не блокировка на 300ms.
- Не использовать CSS `@keyframes` для того, что можно перехватить.

---

## 5. Скорость, инерция и резиновые границы

- Отслеживать последние 80–120ms pointer-событий, чтобы знать velocity.
- При отпускании передавать скорость в spring.
- Проекция покоя (для карты/шторки):
  `projected = current + (v / 1000) * d / (1 - d)`, `d ≈ 0.998`.
- Выбирать ближайшую точку привязки к спроецированной, а не к точке отпускания.
- Rubber-band: чем дальше за границу, тем меньше движение.
  `overshoot * dimension * 0.55 / (dimension + 0.55 * |overshoot|)`.
- Не применять momentum к обычным карточкам и спискам — только к карте,
  шторке и drag-играм.
- На `prefers-reduced-motion` — без инерции, только короткий cross-fade.

---

## 6. Пространственная согласованность

- Шторка шпаргалки входит справа и выходит справа.
- Мобильное меню раскрывается сверху вниз и сворачивается вверх.
- Модальные панели не появляются из центра, если триггер сбоку.
- Тосты — из нижнего правого угла, туда же уходят.
- Фокус после закрытия возвращается на кнопку-триггер.
- Анимация закрытия — зеркало открытия по easing.
- Не менять направление на полпути.

## 7. Материалы и глубина

Наш материал — **васи, камень, вода**, а не стекло Apple. Прозрачность —
функциональная, не декоративная.

- Шапка: полупрозрачная, blur 14–20px, тёплая бумага, тонкая линия.
- Drawer: плотная бумага + scrim; не стеклянная карточка на карточке.
- Тосты: плотная поверхность, мягкая тень.
- Не складывать полупрозрачные поверхности друг на друга.
- Для больших поверхностей — чуть больше blur/тени, чем для чипов.
- Вместо жёсткой линии под шапкой можно использовать мягкий scroll-edge градиент,
  но тонкая линия в японском стиле тоже уместна — не убирать её автоматически.
- Анимация материала: blur + opacity + scale вместе, 250–350ms.
- `prefers-reduced-transparency: reduce` — сделать поверхности плотными,
  убрать blur.
- Прозрачность не должна ухудшать контраст текста.

## 8. Типографика

- Отслеживание зависит от размера: крупные заголовки — отрицательный tracking
  (`-0.02em`), тело — около `0`.
- Leading: крупные заголовки 1.02–1.16, тело 1.6–1.7.
- Иерархия — размер + вес + leading, а не только размер.
- Системные шрифты — база; serif-заголовки и ханко — наша идентичность.
- `font-optical-sizing: auto`; `text-wrap: balance` для заголовков,
  `pretty` для абзацев.
- Отступы и размеры — в `rem`/`em`, чтобы масштабирование текста не ломало макет.
- Не опускать подписи ниже 12px.
- Не заменять serif на «как у Apple»: книга и сад важнее.

---

## 9. Мультимодальная обратная связь

- Визуал и звук — в одном кадре.
- Звук по умолчанию выключен; кнопка mute в шапке.
- Капля — успех/правильный ответ; камень — ошибка; перезвон — достижение.
- Не озвучивать каждый клик и hover.
- Не добавлять haptic-зависимость.
- При ошибке сначала визуальное объяснение, звук — мягкий, не пугающий.
- Не включать звук на autoplay.

## 10. Reduced motion, transparency, contrast

Три независимых сигнала:

```css
@media (prefers-reduced-motion: reduce) {
  /* cross-fade 200ms, без transform/parallax/spring */
}
@media (prefers-reduced-transparency: reduce) {
  /* плотные поверхности, backdrop-filter: none */
}
@media (prefers-contrast: more) {
  /* почти непрозрачный фон, чёткая граница, усиленный контраст */
}
```

- `prefers-reduced-motion`: убрать покачивание бамбука, параллакс камеры,
  пружины, инерцию; оставить статичный 3D-кадр и короткие opacity-переходы.
- Не использовать полноэкранные медленные oscillation (0.2 Гц) как фон.
- Не делать резких скачков яркости при смене темы.
- Большие движущиеся объекты — полупрозрачны, пока движутся.
- Проверить контраст AA в обеих темах.

## 11. Восемь принципов как ревью-линза

1. **Purpose.** Каждый блок урока и каждая кнопка должны иметь причину.
2. **Agency.** Пользователь может вернуться, пропустить, открыть шпаргалку,
   ошибиться и исправить. Никаких принудительных линейных коридоров.
3. **Responsibility.** Прогресс только локально; никакой отправки данных;
   ошибки объясняются бережно.
4. **Familiarity.** Понятные паттерны: карточка = урок, стрелка = дальше,
   ползунок = значение. Метафоры сада не должны ломать привычное.
5. **Flexibility.** Мобильный, планшет, desktop; клавиатура; тёмная тема;
   reduced motion; пользователь может отключить звук.
6. **Simplicity.** Не прятать всё в один экран. Общие действия — на виду,
   продвинутые — на уровень глубже (шпаргалка, библиотека, подсказки).
7. **Craft.** Ровные отступы, единые радиусы, аккуратные состояния, никаких
   «примерно так».
8. **Delight.** Не конфетти, а ощущение: «я спокойно разобрался».

## 12. Чек-лист «как это чувствуется»

- [ ] Кнопка реагирует на нажатие мгновенно.
- [ ] Drag тянется 1:1 и не прыгает в центр.
- [ ] Шторку можно перехватить в движении.
- [ ] Карта на телефоне не имеет жёсткого стопа.
- [ ] Нет пружин там, где не было жеста.
- [ ] Hover не «прыгает».
- [ ] Drawer уходит в ту же сторону, откуда пришёл.
- [ ] Фокус возвращается на триггер.
- [ ] Звук и анимация совпадают по времени.
- [ ] Reduced motion оставляет понятный, но спокойный интерфейс.
- [ ] Полупрозрачность не мешает читать.
- [ ] Контраст и клавиатура проверены.
- [ ] Ощущение: тихий сад, а не iOS-приложение.
