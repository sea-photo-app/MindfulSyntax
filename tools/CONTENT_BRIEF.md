# Бриф автора контента «Сада кода»

Курс Python для человека, который никогда не программировал. Спокойный тон,
простой русский, бытовые аналогии, ошибки — учебный материал, а не наказание.
Один урок = одна мысль + действие. Не раздувать текст водой.

Читай сначала: `CONTENT_EXPANSION.md` (разделы 2, 3, 5), существующие
`js/data/module-0N.js` (формат и тон), `js/checks.js` (как проверяются задания),
`js/games/*.js` (какие настройки принимают виджеты).

## 1. Что и где править

Ты владеешь ТОЛЬКО своими файлами (указаны в задании). Не трогай `lesson.js`,
CSS, `modules.js`, чужие модули и общие файлы. Серверов не запускай.

* `js/data/module-0N.js` — модуль и его уроки.
* `js/data/library/mN.js` — дополнительные данные (схема в §5).

## 2. Нельзя ломать

* ID старых уроков (`m1-l1`…) **не удалять и не переименовывать** — по ним хранится
  прогресс. Если меняешь смысл старого урока — оставь его ID. Новые уроки получают
  новые ID (`m1-l5` и т. д.). Порядок в массиве `lessons` = порядок обучения,
  он не обязан совпадать с номерами ID.
* Формат урока и блоков (см. ниже). Поля `id`, `number`, `title`, `zone`, `tagline`,
  `description`, `icon` модуля сохраняй; `description` обнови под новое число уроков.
* Старые задания и квизы не заменять заглушками: сохраняй, улучшай, расширяй.

## 3. Формат урока

```js
{
  id: "m1-l5",
  title: "…",
  minutes: 6,                       // 4–8
  summary: "…",                     // 1–2 предложения для карточки
  goal: "После урока вы сможете …", // цель урока одним предложением
  recall: "…",                      // подсказка «если забудется» — 1 предложение
  keyIdeas: ["…", "…", "…"],        // РОВНО 3 мысли — итог
  blocks: [ … ],
}
```

Блоки:

* `{ type: "text", html }` — теория, 2–4 абзаца суммарно на смысловой кусок.
* `{ type: "note", tone, title, html }` — tone: `analogy` (аналогия, по одной на урок),
  `tip`, `warn`, `water`, **`why`** («Почему так: …» — короткое объяснение,
  почему Python устроен так, 2 штуки на модуль).
* `{ type: "code", code, caption, runnable?: false }` — запускаемый пример. Всё, что
  без `runnable: false`, валидатор выполняет в Pyodide. В `caption` пиши
  ожидаемый вывод (напр. «Выведет: …») или что рассмотреть.
* `{ type: "quiz", question, options: [..], correct: индекс, explain }`.
* `{ type: "task", title, prompt (html), starter, checks: [..], hints: [..2–3..], success, solution }`.
* `{ type: "widget", widget, config }` — виджеты: `find-error`, `code-order`,
  `variable-box`, `dialog-builder`, `guess-game` (смотри настройки в существующих
  уроках и `js/games/<имя>.js`).

Проверки `checks`: `{type:"contains", value, label}` (по коду),
`{type:"notContains", …}`, `{type:"output", value:[…], label}` (вывод содержит),
`{type:"notOutput", …}`, `{type:"regex", value:"…", label}` (по выводу),
`{type:"noError", label}`.

**Анатомия урока:** цель → теория (5–7 мин чтения) → аналогия → запускаемый пример
с ожидаемым выводом → второй пример (сложнее или с ошибкой для разбора) →
1–2 квиза → 2–3 задания разного уровня («повтори», «измени», «придумай сам») →
игра/виджет, если уместно → итог (keyIdeas) → recall. Практика и итог обязательны.
Каждый модуль заканчивается мини-проектом/челленджем (последний или предпоследний урок).

## 4. Честность заданий (проверяет `tools/validate-content.mjs`)

* `starter` НЕ должен проходить все `checks` сам по себе (нельзя засчитывать пустой код,
  комментарий или готовый ответ). Если starter содержит рабочий `print`, который уже даёт
  нужный вывод — проверка должна требовать ещё что-то (contains/regex).
* Для каждого `task` обязательно поле `solution` — эталон, проходящий все `checks`:
  строка кода или `{ code, answers: ["Аня", "7"] }`, если есть `input()`
  (ответы подставляются по порядку).
* Проверки должны ловить настоящее решение: комбинируй `output` + `contains`/`regex`,
  когда нужно убедиться, что использована конструкция (напр. `if`, `f"`).
* Формулировки `label` — поддерживающие, описывают требование («В выводе есть …»).
* Не используй понятия раньше, чем они объяснены в курсе:
  * модуль 1: только `print()`, строки, числа в `print`, комментарии, SyntaxError;
    без переменных, `input`, `if`, циклов;
  * модуль 2: переменные, арифметика, строки, `input()`, `int()/float()/str()`, f-строки;
    без `if`, циклов, списков, функций;
  * модуль 3: `if/elif/else`, сравнения, `and/or/not`, вложенные условия; без циклов,
    списков, функций, `random`.
  * модуль 4: циклы `for`/`range`/`while`, `break`/`continue`, вложенные циклы, повтор
    строк (`"*" * n`); можно всё из модулей 1–3; без списков, словарей, функций, `random`.
    Перебор символов строки `for ch in "сад"` допустим;
  * модуль 5: списки, срезы, методы списков, словари, `len/sum/min/max/sorted`, `for` по
    спискам и `.items()`; можно всё из модулей 1–4; без функций, `random`, файлов, `try`;
  * модуль 6: `def`, аргументы, `return`, области видимости, значения по умолчанию;
    можно всё из модулей 1–5; без `random`, `import`, файлов, `try`, классов.
  * модуль 7: `import`, `random` (randint, choice, shuffle, sample), `math`, `statistics`
    (mean, median), `datetime` (date(...), timedelta, strftime; НЕ выводи «сегодняшнюю»
    дату в проверяемых примерах — результат не воспроизводим), pip/requirements (команды
    терминала показывай блоками `runnable:false`; для pip есть виджет `pip-sim`); можно всё
    из модулей 1–6; без файлов, `try`, классов. Случайность: в примерах для разбора
    используй `random.seed(7)` (тогда вывод постоянный), а в проверках заданий проверяй
    диапазон/формат (regex), а не конкретное число;
  * модуль 8: проект «Угадай число» растёт по шагам: один и тот же код дописывается урок за
    уроком (уровни сложности, счёт, «теплее/холоднее», красивый вывод, тесты); можно всё
    из модулей 1–7 (функции, random, списки, словари); без `try` (он в модуле 9) и без
    строковых методов (модуль 10) — считайте, что игрок вводит цифры;
  * модуль 9: traceback, `try/except` (с конкретным типом ошибки, `else`, `finally` — кратко),
    `raise`, валидация ввода циклом `while True`, простые тесты через `assert` и печать
    «ожидалось/получилось»; можно всё из модулей 1–8; без файлов, классов.
  * модуль 10: методы строк, `split/join`, `format`/f-строки с форматом, `open()` с `with`
    (чтение, запись `"w"`, дозапись `"a"`), `csv`-подобные таблицы через split; в браузере
    файлы живут в виртуальной папке: пример всегда сначала ПИШЕТ файл, потом читает (так он
    запускается и в Pyodide); можно всё из модулей 1–9;
  * модуль 11: уроки о планировании, чтении и улучшении кода + три проекта (калькулятор,
    викторина, todo-лист) из уже изученного; можно всё из модулей 1–10; без классов;
  * модуль 12: финальный проект «в пять уровней» (MVP → уровни/счёт → сохранение/подсказки →
    своя фича → читаемый код, README, тесты); можно всё из модулей 1–11; без классов.
* Каждый пример проверяй: валидатор запускает его в Pyodide.
* Не копируй уроки; у похожих тем разные примеры и мини-проекты.

Проверка: `node tools/validate-content.mjs mN` (из корня проекта; при синтаксической
ошибке в чужом файле просто повтори через несколько секунд). До «Ошибок нет» — только
предупреждения допустимы, но старайся и их свести к нулю (goal, recall, solution, 3 keyIdeas).

## 5. Дополнительные данные: `js/data/library/mN.js`

Из них собираются страницы «Библиотека» и «Тренажёр», карточки повторения и конспект.
Экспорт по умолчанию:

```js
export default {
  summary: { title: "Конспект: …", points: ["…", …6–9 пунктов…] },
  glossary: [ { term: "строка", definition: "…1–2 предложения…", lesson: "m1-l5" }, … ],   // 7–9
  recipes:  [ { id: "m1-r1", title: "…", code: "…запускаемый код…", explain: "…", lesson: "m1-l2" }, … ], // 3–5
  cards:    [ { id: "m1-c1", front: "Как вывести текст?", back: "print(\"текст\")", lesson: "m1-l2" }, … ], // 5–7
  cheats:   [ { code: "print(x)", text: "показать значение", lesson: "m1-l2" }, … ],        // 5–6
  exercises: [ … 13–15 штук, смесь типов и уровней 1–3 … ],
};
```

Типы упражнений (все поля обязательны для типа):

* `predict` — «предскажи вывод»:
  `{ id, type:"predict", level, prompt, code, expected, options:[…3–4…], correct, explain, lesson }`
  — `expected` ровно равен выводу кода (после trim) и `options[correct] === expected`.
* `read` — «прочитай код»: `{ id, type:"read", level, prompt, code, options, correct, explain, lesson }`
  (вопрос по смыслу кода; код должен запускаться без ошибок).
* `bug` — «найди ошибку»: `{ id, type:"bug", level, prompt, lines:[…строки…], badLine: индекс, fix:"исправленная строка", explain, lesson }`.
* `fill` — «допиши строку»: `{ id, type:"fill", level, prompt, code (с одним ___), answers:["вариант1",…], expected, explain, lesson }`
  — подстановка любого из `answers` вместо `___` должна давать код, который запускается и выводит `expected`.
* `assemble` — «собери код»: `{ id, type:"assemble", level, prompt, pieces:[{id, code}…], solution:[id…], explain, lesson }`
  — собранный в порядке `solution` код должен запускаться без ошибок.

`id` упражнений: `mN-e01`, `mN-e02`, … Уровни: 1 — легко, 2 — средне, 3 — подумать.
Для модулей, где ещё нет `input()` в тренажёре, не используй `input()` в predict/fill. Не используй конструкции, которых ещё нет в курсе (см. §4).

## 6. Стиль

Простой русский, «вы». Аналогии: сад, чай, рецепт, коробки, весы. Без канцелярита
и без «очевидно», «просто». Не пугать. Ошибки — подсказки. Короткие абзацы.
Кавычки текста в коде — любые парные, но единообразно. Не использовать эмодзи.
